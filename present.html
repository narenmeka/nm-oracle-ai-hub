📂 Package Input
PROCEDURE process_invoices ( p_org_id IN NUMBER, p_date_from IN DATE ) IS CURSOR c_inv IS SELECT invoice_id, vendor_id, invoice_amount, status FROM ap_invoices_all WHERE org_id = p_org_id AND invoice_date >= p_date_from; v_count NUMBER := 0; BEGIN FOR r IN c_inv LOOP UPDATE ap_invoices_all SET status = 'PROCESSED' WHERE invoice_id = r.invoice_id; v_count := v_count + 1; END LOOP; END process_invoices;
Analyse with:
Claude Sonnet 4.5 Gemini 2.5 Flash Gemini 2.5 Pro DeepSeek V3 Llama 3.3 70B
🔍 AI Findings
HIGH
Missing COMMIT after bulk UPDATE
Loop updates rows but never commits — transaction left open. Add COMMIT or use SAVEPOINT/ROLLBACK pattern.
HIGH
No exception handler
Any DML error propagates unhandled. Wrap in EXCEPTION block with ROLLBACK and FND_FILE error logging.
MED
Row-by-row cursor loop is slow
Use BULK COLLECT + FORALL for bulk update — 10–50× faster on large invoice datasets.
LOW
Hard-coded status literal
'PROCESSED' should reference FND_LOOKUPS for maintainability and translation support.
INFO
Add FND_FILE audit logging
v_count is tracked but never logged. Add FND_FILE.PUT_LINE for full audit trail.
